## 3. 会社資料のPDFがない場合

PDFがあるかどうかで、2つ目のボタンを切り替えられる設計にする（設定値1つで切り替え）。

| 状態 | 2つ目のボタン | 行き先 |
|---|---|---|
| PDFあり | 会社資料をダウンロード | PDF（またはメールアドレス入力後にPDF） |
| **PDFなし（初期状態）** | **サービス内容を見る** | ページ内のサービスセクション |

- 1つ目のボタン「無料で相談する」は、どちらの状態でも問い合わせ先へつなぐ。
- 「資料請求フォーム」の案は、「後日送られてくる」という約束になってしまうため、採用しない。
- ヘッダーやお問い合わせ欄の資料ボタンも同じ設定で切り替える。
- 前提：問い合わせの受付手段（フォームの送信先、またはメールアドレス）が1つは必要（第7章 D-11）。

## 5. 最も優先すべき目標

**最終目標は「問い合わせ（無料相談）の獲得」で、その一番の壁は「信頼感」。**

1. **信頼感**：数値や取引先といった実績の証拠が使えない今、信頼は「言っていることが明確で、誠実で、一貫していること」でしか作れない。ここが一番の課題。
2. **サービスの理解**：何を、誰に、どう進めてくれる会社なのかが10秒で分かること。
3. **問い合わせ**：相談の敷居を下げる（何を相談できるか、相談後の流れ、費用がかかるか）。
4. **ブランドの独自性**：コンペの審査で目を引く要素。ただし、1〜3を支える役割に留める。

デザインの美しさは目的ではなく、1（信頼感）を伝える手段として位置づける。

## 6. 差別化につながる点と、改善すべき点

**活かすべき強み**
- **社名の物語**（コ×ト＝Koto²）とロゴが一体になっていて、他社がまねできない。
- 正方形・2本の斜線・3つのピースは、ロゴから自然に出てくるモチーフで、足し算の装飾ではない。
- モノクロに青1色という配色は、BtoBらしい落ち着きと品位がある。
- 強みの3項目が TRUE / CONSTANT / SQUARE にきれいに対応している。
- 文言が平易で、「思いつきの施策で予算を消耗させません」のように、顧客側の言葉で書かれている。

**改善すべき点**

| 観点 | 問題 |
|---|---|
| 独自性 | コンセプトの**説明は4回繰り返している**（メインビジュアル、強み、社名、フッター）のに、「具体的にどう違うのか（進め方・体制）」が薄い。マーキー、縁取りの巨大文字、グリッド背景、数値の帯は制作会社サイトによくある定型で、独自性を薄めている |
| 一貫性 | メインビジュアルの「TRUE × CONSTANT = KOTO²」（掛け算）と、社名の「コトの2乗」（同じものを繰り返す）とで、説明が食い違っている。どちらかに統一が必要 |
| 情報設計 | **誰のための会社か**（業種、規模、地域）が書かれていない。サービスカードからの行き先（詳細）がない。「ワンストップ4領域」は他社にも多い訴求 |
| 信頼 | 実績の証拠がないぶん、**人の顔**（代表者やチーム）が見えることが、小規模な会社では最も効く信頼材料になる。現状はゼロ |
| 問い合わせの導線 | CTAは冒頭と末尾に集中していて、サービスや実績を読み終えた直後にない。「無料相談で何ができるか」「相談後の流れ」の説明もない |
| 使いやすさ | SPのメニューが開かない。スライダーが勝手に動く。オープニングで4秒待たされる。1280px以下で見出しが重なる |

## 8. 最終的な改善計画

### 8-1. 現状の問題点
第6章の内容に加え、`HANDOFF.md` 第4章の主な点：
- ロゴの形状のずれ（最大約4%）
- メインビジュアルの3つの不具合（動きの3秒遅れ、進捗バーの逆走、白地に白い文字）
- 自動再生が止められない
- SP版の欠落
- レスポンシブ未対応
- 青の使いすぎ
- デザインのルールがない

### 8-2. 改善する箇所と理由

| 箇所 | 改善内容 | 理由 |
|---|---|---|
| ロゴ | 実物から計測した座標でSVG化し、全ての箇所で同じ形状データを使う（座標は `HANDOFF.md` 第4章・第5章） | 最終形を元のロゴと一致させるため |
| メインビジュアル | コピーと説明文、CTA 2つを冒頭の画面に収める。ロゴで TRUE（上の斜線）→ CONSTANT（下の斜線）→ KOTO²（完成形＋²）を表現し、文字はマークの外に置く | 意味のある動きにするため。読みやすさのため |
| 強み | 「02 CONSTANT」に進め方の要約を入れる（先方の確認後） | 抽象的な主張を具体的な事実で支えるため |
| 社名に込めた想い | 掛け算か2乗か、説明を1つに統一する | 一貫性のため |
| サービス | 対象顧客と、相談できることの例を加える。カードの後にCTAを置く | 理解を深め、問い合わせにつなげるため |
| 実績・ニュース | 「掲載イメージ」と明記し、成果の断定をやめる。実績は手動操作のスライダーにする | 誠実さのため。使いやすさのため |
| 会社概要 | 未確認の項目を空欄として明示する。代表者の写真とひとことを載せる枠を用意（掲載できる場合のみ） | 人の見える信頼感のため |
| 問い合わせ | 「相談の流れ」（3ステップ、内容は要確認）を追加。資料ボタンは第3章の切り替え式にする | 相談の敷居を下げるため |

### 8-3. 追加・削除するセクション
- **削除**：TRUSTED BY、数値の帯（000+ / 00% / 4）、装飾だけの要素（グリッド背景、縁取りの巨大文字、浮いている枠線）
- **追加**：独立したセクションは増やさない。必須の10セクションの中に、「進め方」の要約と「相談の流れ」を組み込む。取引先ロゴの枠は表示しない状態で用意する。

### 8-4. デザインの方針
- **色**：インク・グレー3色・線・薄い背景・青の約6色に絞る。青は「²」「主要なCTA」「現在地」の3つの用途だけに使う。
- **文字・余白・幅**：文字サイズは8段階、余白は8pxを基準、コンテンツ幅は1200/1360pxに整理する。
- **斜線の角度**：ボタンのスイープなどに、Kの斜線の角度（約31.5°）を使う。
- **正方形**：見出し上の記号と ² 以外には使わない。

### 8-5. アニメーションの方針
- **オープニング**：約1.6秒。訪問ごとに初回だけ再生し、スキップできる。回転や跳ねは使わない。
- **メインビジュアル**：自動切り替えは6〜7秒間隔。一時停止できるようにし、ホバーやフォーカスで止まる。
- **ホバー**：0.2〜0.4秒。
- **スクロール連動**：移動量24px以下のフェードだけにする。
- **ずっと動き続ける要素**：なくす。
- **「動きを減らす」設定のとき**：オープニングなし、ロゴは完成形で静止、自動再生なし、の状態で表示する。
- **動きが無効な環境でも、すべての内容が表示されることを保証する。**

### 8-6. スマートフォン対応の方針
- 画面幅を問わず同じコードで表示する。ブレークポイントは 390 / 768 / 1024 / 1280 / 1440。
- SPのメインビジュアルは「コピー → CTA 2つ → ロゴ」の順にし、CTAを最初の画面に入れる。
- メニューは全画面表示にし、キーボード操作にも対応する。追従CTAは、メインビジュアルを過ぎてから表示する。
- 実績は横スワイプで切り替える。タップしやすい大きさ（44px以上）を確保する。ホバーでしか見えない情報は作らない。

### 8-7. 実装方法とその理由
- HTML、CSS、少量のJavaScriptで作り、フレームワークは使わない。ロゴはSVG。
- 色や文字サイズなどのルールはCSS変数にまとめる。実績、ニュース、取引先、PDFの有無はデータとして分けて管理する。
- 理由：外部への依存がなく安定し、そのまま公開でき、CMSにも移しやすい（詳しくは第1章の比較のとおり）。
- 管理はGitHubリポジトリ `kotosquare-` で行い、レビュー用のプレビューリンクを用意する。

### 8-8. 未確定の情報と確認事項
第4章と第7章のとおり。

### 8-9. 制作の優先順位（依頼者の承認後に着手）
1. 土台づくり：HTML構造、デザインルールのCSS変数、SVGロゴ。現行案の見た目のまま移植し、未確認の情報の扱いをここで反映する
2. スマートフォン対応（PCとSPを同時に検証する）
3. ロゴの形成アニメーションとメインビジュアルの切り替え
4. CTAとサービスカードのホバー
5. 控えめなスクロール連動
6. 検証（4画面幅のスクリーンショット、「動きを減らす」設定、実際の操作。Safariは依頼者の協力で確認）。未解決の項目は一覧にして報告する
