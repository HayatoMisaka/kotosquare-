### 1-1. ファイル形式についての注意（重要）

現行コードは通常のHTMLではなく、Claudeのデザインキャンバス用の **「Design Component（.dc.html）」形式** です。ブラウザで直接開いても正しく表示されません。読み解くうえでの規則は以下のとおりです。

- `<script src="./support.js">` は、キャンバスのランタイムを読み込む行です（実体は同梱していません）。
- `<x-dc>` の中身が描画されるマークアップです。
- `<helmet>` の中は `<head>` に差し込まれます（フォントの読み込みと共通CSS）。
- `{{name}}` は、下部スクリプトの `renderVals()` が返す値の差し込みです（式ではなく、値の参照のみ）。
- `<sc-for list="{{slides}}" as="s">` は配列の繰り返し描画です。
- 下部の `<script type="text/x-dc" data-dc-script>` 内の `class Component extends DCLogic` が、React風の状態管理を行います（`this.state` / `this.setState` / `componentDidMount`）。
- `data-props` は、デザインツール上で調整できるパラメータです（`accent` 色、`autoplay`）。
- ロゴ画像は `/_blob/5220061920e1c18b73f6b2ece7be7ba5` という参照になっています。これが `logo_koto_square.png` です。

**通常のHTML/CSS/JSへ移植して作り直してもかまいません**（下記の確認事項1を参照）。

## 2. 依頼者の要件（原文の要約。すべて必須）

あなたは「ハイエンドなBtoBコーポレートサイトを手がけるシニアWebデザイナー兼フロントエンドエンジニア」として、既存デザインを活かしつつ、コンペで採用される可能性を高める改善を行います。

### 2-1. 最重要方針（優先順）
見た目の派手さやアニメーションの数ではなく、以下を優先する。
1. ブランドの独自性
2. 企業としての信頼感
3. 情報設計の分かりやすさ
4. PC・スマートフォン双方での完成度
5. アニメーションの自然さ
6. 実装の安定性

### 2-2. ブランドコンセプト
- 中心となる考え方：**「正しいことを、何度でも²。」**
- **TRUE / CONSTANT / SQUARE** の3つのキーワードを、サイト全体のデザインに反映する。
- 共通モチーフ：**ロゴの正方形**、**Kを構成する2本の斜線**、**3つの黒いピース**。
- 装飾を増やすことが目的ではない。各モチーフが意味を持つように設計する。
- 社名の由来（コード内の文言より）：Constantの「コ」とtrueの「ト」を繰り返しやり続ける＝「コトの2乗（Koto²）」。

### 2-3. 最初に行うこと
コードを変更する前に、プロジェクトを分析する（ファイル構成、PC/SPの構造、CSSの構造、ロゴの実装方法、アニメーションの実装状況、レスポンシブ対応、外部ライブラリ、実装済み・未実装の機能、表示崩れや操作上の問題）。問題点を重要度順に一覧化し、改善計画を示す。**この段階ではコードを変更しない。**
→ 前任AIが実施済み（第3章・第4章）。

### 2-4. ロゴアニメーション
- ロゴは、黒い3つのピースと、白く抜かれた2本の斜線で K を表現している。
- **最終状態では、必ず元のロゴと一致する形状を維持する。**
- 各ピースの位置と形状を正確にする。
- 最終フレームで K が明確に認識できるようにする。
- 右上の小さな青い正方形を「²」の表現として活用する。
- 不必要な回転や大きな跳ねを避ける。
- ロゴ完成後の画面遷移を自然にする。
- PC・スマートフォンで形状が崩れないようにする。
- 可能ならSVGで実装する。ただし既存構造を大幅に壊す変更は避ける。

### 2-5. デザインシステム
カラー、フォント、文字サイズ、行間、余白、コンテンツ幅、ボタン、カード、セクション見出し、アニメーションの速度とイージングを共通ルールとして整理する。
**アクセントカラーは #1E3CFF を基準とし、必要な場所に限定して使う。**

### 2-6. メインビジュアル

- 自動切り替えを採用する場合は、読みやすさ、操作性、動きを減らす設定への対応を優先する。

### 2-7. ページ構成（維持すること）

### 2-8. アニメーション（優先度順に仕上げる）

- すべてを一度に実装しない。

- 装飾のためだけに複雑なアニメーションを追加する
- 既存コードを十分に分析せず、全面的に書き換える
- PC版の修正によってスマートフォン版を壊す
- 動作確認をせずに完成と判断する

### 2-10. 実装後の検証（最低限）

**問題が残っている場合は、完成と報告せず、未解決の項目を明示する。**

### 2-11. 進め方

## 4. 問題点（重要度順）

### 🔴 P0：コンペで信頼を損なう、または明確な不具合

**1. 実在しない情報が、完成しているように見える**
- 「TRUSTED BY」の CLIENT 01〜08 ロゴ枠と「取引先一覧を見る」は、取引先が実在するように見える（禁止事項に該当するおそれ）。必須項目でもない。
- 「000+」「00%」は、数値の形をしたダミーが実績欄に並んでいる。
- 実績タイトル「〜で問い合わせ数を**向上**」は、成果を断定している。
- 「3営業日以内」「24時間受付」「料金の目安」「代表メッセージ」は、未確認の約束や存在しないコンテンツ。
- 「資料ダウンロード」系のボタンはすべて `#contact` に飛ぶだけで、資料が存在しない（要件「実在しない資料を完成しているように見せない」に反する）。

**2. ロゴの形状が実物と最大約4%ずれている**
正式ロゴPNGのマーク部分（約202×203px、ほぼ正方形）を画素単位で走査して計測した（座標はマークを100×100としたときの%）。

| ピース | 現状の clip-path | 実ロゴの計測値（推奨） |
|---|---|---|
| A（左上の三角形） | `0 0, 71.5% 0, 0 42.6%` | `0 0, 71.7% 0, 0 44.0%` |
| B（右の四角形） | `29.5% 41.9%, 100% 0, 100% 100%, 97.3% 100%` | `33.2% 43.1%, 100% 0, 100% 100%, 98.9% 100%` |
| C（左下の四角形） | `0 59.4%, 14.4% 50.8%, 70.8% 100%, 0 100%` | `0 61.2%, 16.4% 51.4%, 71.8% 100%, 0 100%` |

計測の根拠（各高さでの黒/白の切り替わり位置、横方向%）：
- 上の白い斜線：y=10%で55.4→84.7、y=20%で39.1→68.8、y=30%で22.8→53.5、y=40%で6.4→38.1
- 下の白い斜線：y=55%で（C）10.4–20.8｜白｜47.0〜（B）、y=60%で2.0–26.2｜白｜52.5〜、y=70%で0–37.6｜白｜64.4〜、y=80%で0–49.0｜白｜75.7〜、y=90%で0–60.4｜白｜87.6〜、y=99%で0–70.3｜白｜98.0〜
- 上の斜線の傾き：横 −16.3% / 縦 +10%。下の斜線の傾き：横 +11.5% / 縦 +10%
- 480pxの表示では、最大約18pxのずれになる。

※ PNGのロゴには青い正方形は含まれていない。青い正方形（²）は、デザイン案側で追加した要素。

**3. ヒーローの不具合**
- (a) **ピースの「呼吸」が、スライド切り替えより3秒遅れる**。原因：インライン style で `animation-name/duration/timing/fill-mode` だけを上書きしており、`.hk .pc-a{animation: … 3.0s both}` の `animation-delay:3s`（pc-b は3.15s、pc-c は3.3s）が残っている。
- (b) **進捗バーが逆走する**。`bar` の状態が 1→2→3→1 と循環し、3→1 のときに `transition: width 5s linear` で5秒かけて縮む。また、ドットをクリックしてもタイマー（setInterval）と `bar` がリセットされず、表示中のスライドとバーがずれる。初期状態でも slide=0 なのに bar=1 から始まる。
- (c) **「Constant」の文字頭が白い斜線に重なり、白地に白い文字で欠ける**（文字は right:28px / top:168px / 64px。マーク内の横40〜94%・縦35〜48%の範囲で、Bピースの左端は横33〜46%）。
- (d) 3枚目でマーク背景が青になり、K の白い斜線が青く見える。**完成形が元のロゴ（白い斜線）と一致しない。**

**4. 自動再生の操作性とアクセシビリティ**
- ヒーローと**実績スライダーが同じ setInterval で一緒に自動送りされる**（`work` も5秒ごとに進む）。読んでいる途中でカードが動く。
- 一時停止ボタンがなく、ホバーやフォーカスでも止まらない（WCAG 2.2.2 の観点で問題）。
- `prefers-reduced-motion` は CSS だけの対応で、**JSのスライド切り替えは止まらない**。
- スライドの切り替えがスクリーンリーダーに伝わらない。キービジュアルは `role="img"` の中にスライドの文字を含んでいる。
- 実績スライダー：`translateX(-n*408px)` で動かしており、最後の1枚では右側が空白になる。通過済みのカードは opacity 0.25 になる。

**5. SP版の機能と内容の欠落**
- セクションIDがない（`#strength` など）。フッターリンクの行き先が間違っている（「強み」→`#service`、「会社概要」→`#contact-sp`、「お問い合わせ」「資料請求」→`#contact-sp`）。
- ヒーローのCTAが「無料で相談する」の1つだけ（要件は2つ）。
- ヒーローのビジュアルは1枚目で固定（スライドしない）。
- メニューボタンを押しても何も開かない。
- 実績の前へ・次へボタンは動かない（2枚だけの静的な表示）。
- 追従ボタン（`.fab`）が `position:absolute; top:760px` なので、実際のページでは追従しない。さらに、ヒーローのCTA（推定 y≈731〜787px）と重なるおそれがある（未計測、要確認）。
- `a:hover{color:#1E3CFF}` をハードコードしている（PC版は #111114）。

### 🟠 P1：完成度・ブランド性

**6. レスポンシブ未対応**
PC版は幅可変（`expand:fill`）なのにメディアクエリがない。
- h1 は84px で `.ln{width:max-content}` のため、折り返さない。左カラム幅は 1440px表示で約627px、1280px表示で約586px（「正しいことを、」は約590px）なので、**1280px以下でははみ出して右カラムと重なる**おそれがある。
- キービジュアルは、480pxのマーク＋²の正方形（left:496px、幅104px）で約600px幅に固定されている。
- グリッドが3列・2列・「320px + 1fr」などで固定されている。

**7. オープニングが長い・動きが強い**
- 本文が出るまで約4秒かかり、スキップできない。毎回再生される。
- `sqPop` / `supPop` が大きなオーバーシュート（1.56）で、要件「大きな跳ねを避ける」に反する。
- scale(60) のズームは、意味より演出が先に立っている。

**8. 装飾のためだけの要素が多い**
ヒーローのグリッド背景、巨大な縁取り文字（「TRUE × CONSTANT × …」200px、「CONTACT」160px）、浮いている正方形の枠線（OUR NAME、CONTACT）、マーキー。
逆に、**K の2本の斜線という最も独自性の高いモチーフは、ロゴ以外ではほぼ使われていない。**

**9. アクセント色 #1E3CFF の使いすぎ**
見出し上の小ラベル、四角い記号、カード角の四角、タグ、ヘッダーCTA、問い合わせ枠の背景全面、スライド3の背景、カード下線など。「² ＝ 青」という意味が薄まっている。

### 🟡 P2：設計と保守性

**10. デザインシステムがない**
- グレーが12色ある：#111114, #2A2B33, #34353D, #4A4B55, #6B6C76, #8A8B95, #A9AAB4, #C9CAD3, #DADBE2, #E6E7EC, #F0F1F5, #F5F6FA
- 文字サイズが約23段階ある：11, 12, 13, 14, 15, 16, 17, 18, 22, 24, 26, 28, 30, 32, 40, 44, 48, 56, 64, 72, 84, 96, 160/168/200
- 余白の規則がない。
- 見出し上の小ラベル（四角＋英字）、カード、セクション見出しを、同じHTMLで6回以上コピーしている。
- 良い点：主なイージングは `cubic-bezier(.16,1,.3,1)` でおおむね統一されている。

**11. Safari の懸念（コードを読んだうえでの指摘）**
- ヘッダーの `backdrop-filter` に `-webkit-backdrop-filter` がない（Safari 17以前で効かない）。
- ヒーローのグリッドの `mask-image` に `-webkit-mask-image` がない（Safari 15.3以前）。
- `animation-timeline` は Safari 非対応。ただし `@supports` で分けてあるため、コンテンツは表示される（問題なし）。

**12. 見た目だけで機能しない要素**
- ニュースの絞り込み（すべて／お知らせ／実績／コラム）が `<span>` で、押せない。
- サービスカード4枚が自分自身のセクション（`#service`）へのリンクになっている。

## 5. 改善計画（この順で実行する）

### Phase 1｜信頼性とロゴ（P0）
1. 事実でない情報の扱い
   - 「TRUSTED BY」を削除するか、[掲載許諾後に表示] と明記した枠にする（確認事項2）。
   - 数値欄は `[支援社数]` `[継続率]` のような括弧付きの空欄にする。
   - 実績タイトルから成果を断定する表現を外す。
   - 「3営業日以内」「24時間受付」「料金の目安」「代表メッセージ」の表現・リンクは、確認できるまで削除するか空欄にする。
2. 資料CTA：ボタン名は「会社資料をダウンロード」のままにする。ただしリンク先は資料請求フォーム（または問い合わせフォームで「資料請求」を選んだ状態）にして、資料が準備中であることが分かる注記を付ける（確認事項3）。
3. ロゴのSVG化：第4章の計測値で `viewBox="0 0 100 100"` のポリゴン3つを作り、ヘッダー、オープニング、ヒーローで**同じ形状データ**を使う。
   - A: `0,0 71.7,0 0,44.0`
   - B: `33.2,43.1 100,0 100,100 98.9,100`
   - C: `0,61.2 16.4,51.4 71.8,100 0,100`
4. ヒーローの不具合修正：アニメーションの遅延を解消し、スライド、タイマー、進捗バーを1つの状態に統合する（ドット操作でリセット、逆走をなくす）。文字はマークの外（横か下のキャプション）に出し、K の上には重ねない。最終フレームは白い斜線の元ロゴにする。
5. 自動再生の見直し：実績スライダーは手動操作のみにする。ヒーローには一時停止・再生ボタンを付け、ホバーやフォーカスで止める。`matchMedia('(prefers-reduced-motion: reduce)')` が真なら自動再生しない。

### Phase 2｜デザインシステム
- `:root` に CSS変数を定義する。
  - 色：ink #111114、本文グレー、補助グレー、線、薄い背景、アクセント #1E3CFF（グレーは12色→4〜5色に統合）
  - 文字サイズ：8段階程度
  - 余白：8pxを基準にしたスケール
  - コンテンツ幅：1200 / 1360
  - 速度：fast / base / slow の3段階
  - イージング：2種類（`cubic-bezier(.16,1,.3,1)` と、入れ替え用の `cubic-bezier(.77,0,.18,1)`）。オーバーシュートは使わない
- ボタン、カード、セクション見出し（小ラベル＋h2）を共通クラスにする。
- 青は **「²」・主要CTA・現在地（スライドの現在位置など）** の3つの用途に限定する。

### Phase 3｜ロゴアニメーションとメインビジュアル
- オープニングを約1.6秒に短くする。
  - 3ピースがそれぞれの斜線の方向に沿って、数%だけ移動して閉じる。回転や跳ねは使わない。
  - 最後に青い ² の正方形を置く（不透明度と、ごく小さなスケール）。
  - その後、マークがヘッダーのロゴ位置へ縮んで移動する（FLIP）か、静かにクロスフェードしてページを始める。
  - クリックでスキップできるようにする。セッション中は初回のみ再生する。
- ヒーローで TRUE → CONSTANT → KOTO² を表現する（意味の割り当て）。
  - **TRUE**：上の白い斜線（＝正しい方向）を強調
  - **CONSTANT**：平行する下の白い斜線（＝繰り返し）を強調
  - **KOTO²**：K の完成＋青い ² の正方形
  - **最終フレームは必ず元のロゴと完全に一致させる。**

### Phase 4｜レスポンシブとSP版の統一
- PC版にブレークポイント（1280 / 1024 / 768）を追加する。h1 は `clamp()` で縮め、キービジュアルは % で拡大縮小する。
- SP版を、PC版と同じ内容・ID・リンクに揃える。
  - ヒーローのCTAを2つにする。
  - メニューを開閉できるようにする。
  - 実績スライダーを動作させる。
  - 追従ボタンを `position:fixed` 相当にし、ヒーローのCTAと重ならないようにする（ヒーロー通過後に表示）。

### Phase 5｜ホバーとスクロール
- ボタンのスイープの角度を、K の斜線の角度（上の斜線：水平から約31.5°）に合わせる。
- サービスカード：ホバー時に矢印の枠が青い正方形（²）になる。浮き上がりは控えめにする。
- スクロール連動は、移動量を24px以下・不透明度中心にする。
- 巨大な縁取り文字のパララックスや、浮いている枠線など、意味のない装飾は削除するか、モチーフに置き換える。

### Phase 6｜検証
- 表示幅 1440 / 1280 / 1024 / 768 / 390 でスクリーンショットを撮り、見出しの改行、重なり、欠落を確認する。
- `prefers-reduced-motion: reduce` をエミュレートして確認する。
- ナビゲーション、スライダー、CTA、メニューを実際に操作して確認する。
- **Safari（WebKit）の実機またはエミュレーションで確認する。** 前任の環境には Chromium しかなく、Safari は未検証。
- 未解決の項目が残っていれば、完成とは報告せず、一覧にして示す。
